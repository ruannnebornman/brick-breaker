# v0.23 Playtest Fix Plan

Status: Implemented for `v0.23.0`.

## Playtest Context

- Current visible build: `v0.22.0`.
- Latest manual run reached Level 51.
- Overall feel was strong and fun enough to justify a focused balance/bug pass instead of broad new feature work.

## Goals

- Preserve the fast, chaotic, high-upgrade fun from the Level 1-51 run.
- Remove progression blockers that can trap a run in an unclickable state.
- Make bosses feel like meaningful 10-level checkpoints again.
- Prevent cannon-only play before balls are launched.
- Let multiball become a bigger identity upgrade without making early levels unreadable.

## Issues To Address

### 1. Bosses End Too Fast

Observed:
- Boss fights are currently dying before their attack patterns and identities have time to matter.
- This became especially visible once the player had several strong run upgrades.

Implemented fix:
- Increased all major 10th-level bosses with a `3x` HP multiplier.
- Left the Level 5 Training Core unchanged so it remains a tutorial boss.
- Kept `10x` as a future tuning option only if `3x` still melts too quickly in mid-run playtests.

Acceptance criteria:
- Level 10+ major bosses last long enough to show at least one full attack cycle.
- Boss fights feel like a spike in focus, not a slow grind.
- A strong build should still feel powerful, but not delete bosses instantly.

### 2. Upgrade Selection Can Run Out Of Choices

Observed:
- At Level 51, the upgrade screen showed no cards.
- The run became stuck because Main Menu was the only clickable option.
- Continue restored the same pending upgrade state, so the player was trapped.

Implemented fix:
- Added fallback-only repeatable upgrades that appear when the normal upgrade pool has no valid choices.
- Fallback choices currently cover ball damage, crit chance, and per-level shield relaunches.
- Existing pending reward saves still store concrete choices, while newly generated exhausted pools now produce valid choices.

Acceptance criteria:
- Upgrade select always has at least one valid way forward.
- Continuing a saved run can never loop into an unwinnable empty upgrade screen.
- Exhausting unique upgrades becomes a pleasant late-run problem, not a hard progression bug.

### 3. Cannon Can Fire Before Ball Launch

Observed:
- The cannon can be fired while all balls are still stuck to the paddle.
- From around Level 40, this allowed clearing with cannon shots without launching the balls.

Implemented fix:
- Cannon firing is gated until at least one ball has been launched in the current level.
- Cannon HUD stays visible as `Cannon Locked` before launch.
- The launch gate resets on each new level and after life-loss respawns.

Acceptance criteria:
- Pressing `F` before launch does nothing or gives a harmless unavailable feedback state.
- Cannon becomes usable immediately after the first ball launch.
- Cannon remains usable during normal play and after later relaunches.

### 4. Multiball Is The Most Fun Upgrade

Observed:
- More balls was by far the most exciting upgrade.
- The player reached 4 balls but often lost several almost immediately.
- There is appetite for a much higher cap, around 10 balls.

Implemented fix:
- Raised the multiball upgrade max to allow 10 total balls.
- Left deeper ball-save and visual-clutter tuning for follow-up playtests once 6-10 ball builds are observed.

Acceptance criteria:
- A player can build toward 8-10 balls in a long run.
- Losing some balls feels natural, not like the upgrade immediately evaporated.
- The screen remains readable with many balls, projectiles, particles, and boss attacks.

## Suggested v0.23 Work Order

1. Fixed the empty upgrade selection blocker.
2. Added the cannon pre-launch gate.
3. Increased boss HP with a conservative `3x` first pass.
4. Raised the multiball cap to 10 total balls.
5. Versioned the build as `v0.23.0`.
6. Fresh manual playtest to at least Level 55 remains the next validation target.

## Non-Goals For This Pass

- Do not add new biomes, bosses, hazards, enemies, or permanent shop systems.
- Do not redesign the upgrade system UI beyond what is required to avoid empty choices.
- Do not start Milestone 10 juice work until v0.23 removes these blockers.

## Verification Plan

- Unit/module checks:
  - upgrade pool exhaustion produces fallback choices,
  - continue-from-pending-reward never traps the player,
  - cannon cannot fire before first launch,
  - multiball cap and stat stacking match the new intended max.
- Browser smoke checks:
  - start a fresh run,
  - jump/debug-progress to boss levels,
  - verify boss fights last longer,
  - verify the upgrade screen always has a playable action,
  - verify version stamp after bump.
- Manual playtest:
  - play through Level 51 again and confirm the previous blocker is gone.
