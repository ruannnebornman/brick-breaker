# v0.24 Reward Block and Pickup Plan

Status: Implemented for `v0.24.0`.

## Core Idea

Move most upgrade excitement out of the post-level reward screen and into the level itself.

Instead of clearing a stage and choosing cards, some bricks become reward blocks. Destroying a reward block spawns a falling pickup. Catching the pickup with the paddle applies the reward immediately or stores it for future levels, depending on reward type.

Stage clear can still show a small randomized bonus screen for coins, minor temporary rewards, or smaller extra choices, but the main upgrades should come from blocks during play. The excitement moves into moment-to-moment play: see a reward block, break it, decide whether to risk paddle position to catch the drop.

## Design Goals

- Make upgrades feel physical and arcade-like.
- Reduce reliance on post-level choice interruptions while keeping room for small stage-clear bonuses.
- Let stages carry distinct reward identities, such as one permanent upgrade block plus two short-term multiball blocks.
- Support temporary, run-long, and permanent progression rewards.
- Keep the save model declarative and recoverable after reload.
- Avoid making missed pickups feel unfair when the screen is already chaotic.

## Review Decisions

- Permanent rewards should not be missable once their block is destroyed in a cleared level.
- If a reward block is destroyed last, all still-falling upgrades should auto-collect before moving to the next stage.
- For now, all blocks should be cleared. Optional side-reward blocks can be tested later.
- Keep a stage-clear reward screen, but make it smaller and use the same reward randomness where possible.
- Valuable pickups should use slower fall speeds and mild magnetism.
- Reward block identity should be visible before breaking the block.
- Multi-level temporary rewards include the current level by default.
- Saves should commit only the last completed level's loadout. Mid-level pickups are not saved as durable progress until level clear.

## Reward Types

### 1. Instant Temporary Pickups

Applied immediately when caught.

Examples:
- `+3 balls for this level`
- `Cannon overdrive for 12 seconds`
- `Ball speed surge for 15 seconds`
- `One shield for this level`

Recommended use:
- Common reward blocks.
- Short-lived excitement.
- Safe to place in regular generated levels.

### 2. Timed Multi-Level Upgrades

Applied for a fixed number of future levels.

Examples:
- `+3 balls for 2 levels`
- `+25% cannon fire rate for the next 3 levels`
- `Fire effects boosted for 2 levels`

Recommended save shape:

```js
activeRun.temporaryUpgrades = [
  {
    id: "temp_multiball_3",
    remainingLevels: 2,
    sourceLevel: 17
  }
];
```

Duration should decrement when a level starts or when a level is completed, but not both. Recommended: decrement on level completion after the bonus affected that level.

### 3. Run Upgrades

Equivalent to today’s run upgrades, lasting until game over or victory.

Examples:
- `+1 launched ball`
- `Add Lightning`
- `+4 ball damage`
- `Guard Cannon`

Recommended use:
- Replace the current post-level upgrade cards.
- Reward blocks can either contain a known reward or roll from a weighted table when the level is generated.

### 4. Permanent Upgrades

Persist beyond the current run.

Examples:
- `Start each run with +1 coin bonus level reward`
- `Permanent +1% crit chance`
- `Unlock one extra starting upgrade draft`
- `Tiny permanent paddle width bonus`

Recommended save shape:

```js
profile.permanentUpgrades = {
  perm_crit_1: 1,
  perm_starting_paddle: 2
};
```

Recommended rule:
- Permanent pickups should be rare and highly readable.
- Permanent rewards should be guaranteed once their block is destroyed and the level is cleared.
- If represented as a falling pickup, a permanent reward should fall slowly, use strong magnetism, and auto-collect on level clear.
- Bosses or challenge stages are good places for guaranteed permanent blocks.

### 5. Stage-Clear Bonuses

Smaller bonus choices shown after the level is cleared.

Examples:
- `+35 coins`
- `+1 shield for the next level`
- `+1 ball for 1 level`
- `Small damage boost for 2 levels`

Recommended use:
- Keep a little post-stage anticipation.
- Give the player something even if they missed most pickups.
- Use the same seeded randomness and reward weighting as reward blocks where possible.
- Keep these weaker than in-level reward blocks so the game still rewards active pickup play.

## Reward Block Model

Reward blocks should be normal bricks with extra reward metadata.

Example level data:

```js
{
  type: "reward_cache",
  x: 420,
  y: 128,
  width: 88,
  height: 34,
  hp: 2,
  requiredForClear: true,
  reward: {
    kind: "temporaryMultiLevel",
    id: "temp_multiball_3",
    label: "+3 balls",
    durationLevels: 2,
    statModifiers: { ballCountAdd: 3 }
  }
}
```

Recommended fields:
- `reward.kind`: `instant`, `temporaryMultiLevel`, `runUpgrade`, `permanentUpgrade`, or `currency`.
- `reward.id`: stable identifier.
- `reward.label`: short pickup text.
- `reward.rarity`: affects color and fall behavior.
- `reward.durationLevels`: only for timed multi-level upgrades.
- `reward.statModifiers`: stat changes for temporary rewards.
- `reward.upgradeId`: references an existing run upgrade when possible.
- `reward.permanentId`: references a permanent upgrade definition.

## Falling Pickup Model

Add a lightweight pickup entity spawned when a reward block is destroyed.

Recommended fields:

```js
{
  id,
  kind: "pickup",
  reward,
  x,
  y,
  vy,
  radius,
  age,
  active,
  magnetStrength,
  expireBelowY
}
```

Pickup behavior:
- Falls downward at a readable speed.
- Collides with paddle rect.
- On catch, applies reward and plays an obvious feedback effect.
- If missed, disappears below the arena.
- Valuable pickups fall slower and can have a mild paddle magnet radius.
- All still-falling pickups auto-collect when the level clear condition is met.

Recommended first-pass speeds:
- Common temporary: `150-175 px/s`
- Run upgrade: `130-155 px/s`
- Permanent: `95-120 px/s`

## Flow Changes

Current flow:

1. Clear level.
2. Grant coins.
3. Save pending reward.
4. Show upgrade cards.
5. Pick upgrade.
6. Start next level.

Proposed flow:

1. Generate level with reward block definitions.
2. Destroy reward blocks during play.
3. Spawn falling pickups.
4. Catch pickups to apply rewards.
5. Clear all blocks.
6. Auto-collect any still-falling pickups.
7. Commit staged rewards to the active run/profile save.
8. Show a small stage-clear bonus screen for coins or minor temporary rewards.
9. Start the next level.

Important:
- In-level reward blocks carry the main upgrade excitement.
- Stage-clear choices should be smaller and faster than the current upgrade-card flow.
- Coins can exist both as pickups and as stage-clear bonuses.
- Pending reward save state can be removed after migration or kept only for old-save recovery.
- Reward blocks count toward clear for now because the current test rule is "clear all blocks."

## Upgrade Application Rules

### Instant Level Rewards

Apply directly to the current level and current stats.

Example:
- Catch `+3 balls this level`.
- Spawn 3 additional active stuck/launched balls near the paddle or current ball cluster.
- The bonus does not persist after level clear.

### Multi-Level Temporary Rewards

Apply immediately for the current level and stage the committed duration for level clear.

Example:
- Catch `+3 balls for 2 levels`.
- Current level receives +3 balls immediately.
- The next two level starts also include +3 balls.

Duration decision:
- Temporary duration includes the current level by default.
- Label as `+3 balls for 2 levels` rather than `next 2 levels`.

### Run Upgrades

Apply immediately for the current level and stage the upgrade for commit on level clear.

Example:
- Catch `Storm Relay`.
- Stage `lightning_chain` for `activeRun.runUpgrades`.
- Recalculate stats immediately and update active balls/projectiles where reasonable.
- If the player quits before clearing the level, the staged run upgrade is discarded with the abandoned attempt.

### Permanent Upgrades

Add to `profile.permanentUpgrades`.

Example:
- Catch `Permanent Crit Core`.
- Increment `profile.permanentUpgrades.perm_crit`.
- Stage the permanent reward during the level.
- Commit it to the profile only when the level is cleared.

Permanent upgrades need a small definition table before implementation.

## Save and Reload Requirements

The current save should not store live entities. Keep that rule.

Use a checkpoint model:

- Save only the committed loadout from the last completed level or the current level start.
- During a level, caught pickups are staged in transient level state.
- If the player quits or reloads mid-level, restart that level from the last committed loadout.
- Do not load mid-level buffs picked up during the abandoned attempt.
- On level clear, auto-collect remaining falling pickups, commit staged rewards, advance level, and save.

Example:
- Player starts Level 24 with 4 balls and `+4 damage`.
- During Level 24, they catch `+3 balls for 2 levels`.
- They quit before clearing Level 24.
- Continue reloads Level 24 with the committed 4 balls and `+4 damage`, not the newly caught temporary buff.
- If they clear Level 24, the temporary buff is committed for Level 25 according to its remaining duration.

Recommended committed save data:
- Active run seed.
- Current level.
- Lives.
- Committed run upgrades.
- Committed temporary upgrades.
- Coins earned.
- Profile permanent upgrades.

Recommended transient level state:

```js
level.stagedRewards = {
  runUpgrades: ["lightning_chain"],
  temporaryUpgrades: [
    { id: "temp_multiball_3", remainingLevels: 2 }
  ],
  permanentUpgrades: ["perm_crit_1"],
  coins: 30
};
```

This makes reload behavior simple and avoids partial mid-level save bugs.

## Anti-Farming Rules

Important because reward blocks can be permanent.

- Reward blocks need stable IDs generated from level number, slot, and seed.
- Caught rewards are staged during the level.
- Level clear is the only commit point for durable reward progress.
- Reloading or quitting mid-level discards staged rewards and restarts from the last committed loadout.
- Auto-collecting falling pickups on clear prevents losing rewards because the final brick was a reward block.
- Starting a new run resets run and temporary collected reward records, but not profile permanent upgrades.

## UI and Readability

Reward block visuals:
- Common temporary: cyan/green core.
- Run upgrade: gold core.
- Multi-level temporary: blue core with small timer pips.
- Permanent: white/gold prism core.

Pickup visuals:
- Use a symbol or short label inside a small glowing capsule.
- Avoid long text while falling.
- Show a short floating text on catch: `+3 Balls · 2 Levels`.

HUD:
- Add compact temporary upgrade indicators, such as `+3 Balls: 2`.
- Keep permanent upgrade notifications brief.

## Implementation Slices

### Slice 1: Reward Block and Pickup Foundation

- Add reward metadata support to bricks.
- Add `Pickup` entity and `PickupSystem`.
- Spawn pickups when reward bricks are destroyed.
- Add paddle catch collision.
- Add simple instant temporary rewards.

Done when:
- A test level can drop a `+3 balls this level` pickup and catching it applies immediately.

### Slice 2: Rework Post-Level Upgrade Cards

- Move major upgrade choices into reward blocks.
- Keep a smaller stage-clear bonus screen for coins and minor temporary rewards.
- Generate reward blocks in levels.
- Auto-collect falling pickups before opening the stage-clear bonus.
- Keep old pending reward recovery for existing saves only.

Done when:
- Clearing a level no longer grants the main run-upgrade cards.
- Stage-clear bonuses are smaller and faster than the current upgrade screen.
- Normal run upgrades can be earned from blocks.

### Slice 3: Multi-Level Temporary Upgrades

- Add `activeRun.temporaryUpgrades`.
- Apply temporary upgrades in stat calculation.
- Decrement duration consistently.
- Display temporary effects in HUD.

Done when:
- Catching `+3 balls for 2 levels` affects the current level and future levels, then expires.

### Slice 4: Permanent Upgrade Definitions

- Add `src/data/permanentUpgrades.js`.
- Add profile persistence and save normalization.
- Add rare permanent reward blocks.

Done when:
- Catching a permanent pickup survives game over, new run, reload, and browser restart.

### Slice 5: Generation and Balance

- Add reward slots to generated level rules.
- Tune reward frequency by level range and biome.
- Add boss/challenge reward blocks.
- Prevent reward blocks from spawning unreachable or visually hidden.

Done when:
- A 20+ level playtest has steady reward excitement without flooding the player.

## Ten Example Stages

### 1. Level 3 - Training Cache

Purpose:
- Teach that glowing blocks drop pickups.

Reward setup:
- 1 common reward block near the center.
- Drops `+1 ball this level`.

Stage feel:
- Easy catch, low pressure, obvious tutorial moment.

### 2. Level 7 - Split Choice Lane

Purpose:
- Teach risk/reward paddle movement.

Reward setup:
- 2 reward blocks on opposite sides.
- Left drops `+4 ball damage this run`.
- Right drops `+3 balls this level`.

Stage feel:
- Player can probably catch one, maybe both with skill.

### 3. Level 10 - Mossback Trophy

Purpose:
- Make first major boss reward memorable.

Reward setup:
- Boss summons or reveals 1 gold reward block at 50% HP.
- Drops a run upgrade from the normal upgrade pool.

Stage feel:
- Boss lasts longer, reward appears mid-fight, player must decide between survival and catch.

### 4. Level 14 - Double Serve Trial

Purpose:
- Introduce multi-level temporary upgrades.

Reward setup:
- 2 blue temporary reward blocks.
- Each drops `+3 balls for 2 levels`.

Stage feel:
- Catching both can create a wild 6-ball spike for the current and next level.

### 5. Level 18 - Drone Escort Cache

Purpose:
- Combine enemy pressure with reward chase.

Reward setup:
- 1 gold run-upgrade block behind or near the drone.
- 1 common shield pickup block near the lower-middle area.

Stage feel:
- The shield pickup helps offset projectile pressure if caught.

### 6. Level 20 - Ember Wyrm Hoard

Purpose:
- Boss reward identity.

Reward setup:
- 1 guaranteed permanent upgrade block.
- 1 temporary `Fire Boost for 3 levels` block.

Stage feel:
- Permanent pickup has a strong visual treatment and is guaranteed if the level is cleared after the block is destroyed.

### 7. Level 27 - Cannon Battery

Purpose:
- Support cannon builds without menu cards.

Reward setup:
- 3 small reward blocks in a row.
- Possible drops: `Guard Cannon`, `Cannon Tuning`, or `Cannon Overdrive for this level`.

Stage feel:
- A cannon-focused stage that can unlock or spike the build.

### 8. Level 33 - Frost Bank

Purpose:
- Element-targeted reward stage.

Reward setup:
- 1 run upgrade block weighted toward Frost.
- 2 temporary brittle/chill boost blocks.

Stage feel:
- If the player catches all rewards, the next boss approach becomes a Frost-heavy burst window.

### 9. Level 41 - Hazard Vault

Purpose:
- Make blockers matter without direct damage.

Reward setup:
- 1 permanent block behind a thorn/blocker lane.
- 2 common temporary blocks in safer lanes.

Stage feel:
- The permanent reward asks for a deliberate lane decision, then auto-collects on clear if still falling.

### 10. Level 50 - Storm Citadel Prize Fight

Purpose:
- Mid-campaign checkpoint with big reward drama.

Reward setup:
- Boss starts with no reward blocks.
- At phase 2, spawns 2 gold run-upgrade blocks.
- At phase 3, spawns 1 permanent upgrade block.

Stage feel:
- Player gets a strong reason to keep boss phases alive and engage with attacks instead of only racing the kill.

## Open Questions For Review

- Should reward pickups be catch-only, or can balls collect them too?
- How often should permanent upgrade blocks appear: every boss, every 10 levels, or rare random stages?
- How small should stage-clear bonuses be compared with reward-block upgrades?
- If a non-permanent pickup has already fallen below the arena before clear, should it stay missed or return as a smaller stage-clear consolation?

## Recommended First Implementation Target

Implemented first:

- Reward metadata on normal bricks.
- Falling pickup entity and pickup system.
- In-level instant, run, temporary, permanent, and currency reward handling.
- Auto-collect of active pickups on clear.
- Checkpoint-style staged rewards that commit only on level clear.
- Smaller stage-clear bonus choices.
- Generated and boss reward-block placement.

Future follow-up:
- Tune reward frequency and exact reward tables through playtesting.
- Decide how often permanent blocks should appear long-term.
- Add richer pickup audio/visual juice after the mechanics feel right.
