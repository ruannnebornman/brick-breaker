# v0.26 Boss Element Choices and Run-Scoped Brick Upgrades Plan

Status: Review draft. Do not implement until approved.

This plan follows the chosen direction in [Upgrade Catalog](UPGRADE_CATALOG.md).

## Core Direction

- Permanent store upgrades are long-term non-element progression.
- Brick reward drops are the same upgrade types as the store, but they only last for the current run.
- Boss clears open the upgrade choice screen.
- Boss upgrade choices are always elements.
- Elements are binary for the run: one Fire, one Water, one Earth, etc.
- Elements do not stack, do not strengthen, and cannot duplicate.
- Element upgrades reset at the end of a run.
- Temporary upgrades stay removed.
- Normal stage clears do not show an upgrade screen.
- Reward block drops fly into the paddle immediately instead of drifting down.
- Boss clears award coins, then continue into the next stage after the boss element choice.
- Normal-level coin rewards are deferred until later economy tuning.

## Problem

The current reward model has several feel problems:

- Permanent upgrades use unclear names like `Power`, `Guard`, `Focus`, and `Ward`.
- Temporary upgrades are hard to read, especially when they expire.
- Element upgrades feel buried by normal reward drops.
- The end-level reward screen interrupts normal levels and can show too few options.
- Falling pickups feel slow and can make the player wonder whether they got the reward.
- Coins exist, but they do not yet have a strong between-run purpose.

The new direction separates the reward types:

- Store upgrades are permanent progression.
- Brick drops are temporary-for-run stat progression using the store upgrade list.
- Boss screens are run-only element choices.
- Coins are the bridge between clearing levels and long-term power.

## Upgrade Split

### Permanent Store Upgrades

Permanent upgrades are bought outside the run loop. They apply at the start of every level.

Store costs double each stack:

`next cost = first cost * 2^ownedStacks`

Permanent upgrades from the catalog:

| Upgrade | ID | Effect | Max Stacks | First Cost |
| --- | --- | --- | --- | --- |
| Ball Damage | `perm_ball_damage` | +1 ball damage forever | 25 | 25 coins |
| Ball Speed | `perm_ball_speed` | +8 ball speed forever | 15 | 25 coins |
| Extra Ball | `perm_extra_ball` | +1 launched ball forever | 10 | 80 coins |
| Shield Charge | `perm_shield_charge` | +1 shielded relaunch each level forever | 3 | 100 coins |
| Cannon Unlock | `perm_cannon_unlock` | Unlock paddle cannon forever | 1 | 250 coins |
| Cannon Power | `perm_cannon_power` | +0.12 cannon damage multiplier | 3 | 150 coins |
| Cannon Cooldown | `perm_cannon_cooldown` | -0.18 cannon cooldown | 3 | 150 coins |
| Cannon Splitter | `perm_cannon_splitter` | +1 cannon projectile | 2 | 300 coins |
| Pierce Training | `perm_pierce_training` | +5% non-boss pierce chance | 5 | 120 coins |

### Run-Scoped Brick Drops

Reward blocks drop run-scoped versions of the store upgrades.

Example:
- Store has `+1 Ball Damage`.
- A brick drop gives `+1 Ball Damage` for the current run.
- During that run, the two stack together.
- When the run ends, the brick-drop stack disappears and the player returns to the store baseline.

Rules:

- Brick drops use the same upgrade list and effects as the store.
- Brick-drop upgrades are stored on the active run, not the profile.
- Brick-drop upgrades reset when the run ends.
- Brick-drop upgrades stack with store upgrades for effective stats.
- Store stacks and run-scoped brick-drop stacks share the same max-stack cap.
- If the store already has an upgrade maxed, that upgrade does not spawn from brick rewards.
- If store stacks plus current run stacks reach an upgrade's max, that upgrade stops spawning for the rest of the run.
- Brick drops do not grant elements.
- Brick drops do not grant coins.
- Brick drops are collected through the instant paddle-absorption animation.

Coin bag fallback:
- If no run-scoped brick upgrades are available, the reward block spawns a coin bag instead.
- Coin bag value is 10% of the boss coin reward for that stage set.
- For v0.26, boss rewards are 1000 coins, so exhausted-pool coin bags are 100 coins.
- Coin bags are a fallback only; they should not appear while at least one valid run-scoped brick upgrade can still spawn.

Run-scoped brick drop examples:

| Drop | Effect | Run Behavior |
| --- | --- | --- |
| Ball Damage | +1 ball damage | Adds on top of store damage until the run ends. |
| Ball Speed | +8 ball speed | Adds on top of store speed until the run ends. |
| Extra Ball | +1 launched ball | Adds one run-only ball count on top of store ball count. |
| Shield Charge | +1 shielded relaunch each level | Adds one run-only shield charge per level. |
| Cannon Power | +0.12 cannon damage multiplier | Improves cannon damage until the run ends. |
| Cannon Cooldown | -0.18 cannon cooldown | Improves cannon cadence until the run ends. |
| Cannon Splitter | +1 cannon projectile | Adds a run-only cannon projectile until the run ends. |
| Pierce Training | +5% non-boss pierce chance | Adds run-only pierce chance until the run ends. |

### Boss Element Choice Screen

Boss clears are the exception to the removed stage-clear screen.

Decision:

- Normal levels do not show an upgrade screen.
- Boss levels show an upgrade screen after the boss dies.
- The boss screen offers three element choices.
- The player picks one element.
- The next stage starts after the boss element choice.

Element choice rules:

- Classic elements are Common.
- Arcade Physics elements are Uncommon.
- Mystic Material elements are Rare.
- Common family roll: 70%.
- Uncommon family roll: 25%.
- Rare family roll: 5%.
- Elements cannot duplicate within the same run.
- If a rolled family has no unowned elements left, reroll or normalize into families that still have unowned elements.
- Once all Classic elements are owned, Common rolls stop producing Classic choices; by that point only unowned Arcade/Mystic elements can appear.
- If fewer than three unowned elements remain, fill missing boss choice slots with coin rewards.
- If no unowned elements remain, the boss upgrade screen can offer coin rewards only.

Element families:

| Family | Rarity | Weight | Elements |
| --- | --- | --- | --- |
| Classic | Common | 70% | Fire, Water, Wind, Earth |
| Arcade Physics | Uncommon | 25% | Spark, Resin, Echo, Gravity |
| Mystic Material | Rare | 5% | Ash, Glass, Mist, Iron |

Element ownership rules:

- Each base element is binary within a run.
- The player can only get each base element once per run.
- There is no stronger version, rank, or stack of an element.
- Once an element is owned, that same element is removed from boss choice pools.

## Element Combo System

The element combo catalog is the target shape.

Rules:

- 2-type combos are specific named reactions.
- 3-type combos are advanced reactions based on dominant family.
- 4-type combos are major super reactions.
- Collecting all 12 base elements activates `The First Break`.

Implementation guidance:

- Implement all 12 base elements in v0.26.
- Start combo reactions with a small working set of two-type combos.
- Keep the full catalog in data so new combos can be enabled without redesigning the system.
- Avoid implementing every reaction as a unique bespoke class if a shared reaction engine can cover marks, pulses, splash, chains, fields, delayed hits, and shards.
- The UI should show discovered combo names as the player builds them.

Combo activation:

- Combo reactions trigger immediately when the player owns the required elements.
- Combo reactions do not require a separate combo/catalyst reward pick.
- Base element effects remain active while owned for the run.
- Combo effects do not stack every possible pair/reaction at once.
- The active combo is the highest-order matching combo available from the player's current elements.
- Higher-order combos replace lower-order combo reactions in the active combo slot.
- Example: Fire + Water activates `Steam`; adding Earth changes the active combo to `Geyserstone` instead of keeping `Steam`, `Magma`, and `Mud` active.
- Example: Fire + Water + Wind activates `Monsoon Flame` instead of keeping `Steam`, `Wildfire`, and `Tempest` active.
- If the player collects all 12 base elements in a normal run, `The First Break` activates immediately.
- When a new combo is discovered, gameplay pauses briefly.
- The screen shows a large explosive reveal moment with the combo name.
- The reveal should feel like an event, not a quiet HUD update.
- After the reveal, the combo appears in the side UI with its description from the upgrade catalog.
- If multiple combos unlock at once, queue the reveals so they are readable.

Side UI:

- Active elements and the active combo appear in the same side panel.
- Base elements show compact icons/statuses.
- The active combo shows its name and catalog description under it.
- If a higher-order combo replaces a lower-order combo, the side panel updates to the new combo.

Acceptance criteria:

- All 12 base elements exist.
- Boss choices prioritize unowned elements, with coin fallback slots only when fewer than three unowned elements remain.
- Boss choices never offer an element already owned this run.
- Base elements do not stack or strengthen.
- The player can understand which elements they have this run.
- The player can see the current highest-order active combo reaction.
- `The First Break` is reachable in normal runs if all 12 base elements are collected.
- New combos get a large pause-and-explosion reveal with the combo name.
- Active elements and active combo appear on the same side panel.
- Active combo appears with its gameplay description.

## Reward Block Flow

Reward acquisition should be immediate and physical.

Decision:

- Reward pickups no longer slowly drift down.
- When a reward block breaks, the reward immediately flies from the block to the paddle.
- On arrival, the paddle bursts with the upgrade effect.
- The reward applies automatically.
- The player never loses a reward because they failed to catch it.

Motion direction:

- Start at the destroyed reward block position.
- Ease or accelerate quickly toward the paddle center.
- Arrive in a short, punchy time window.
- Trigger a paddle burst, flash, particles, or shockwave.
- Show floating text such as `+1 Ball Damage` or `+1 Ball`.

Acceptance criteria:

- Reward pickups zoom into the paddle instead of drifting downward.
- Breaking a reward block always grants the reward after the quick zoom animation.
- The reward motion clearly travels from the block to the paddle.
- The paddle impact feels satisfying and readable.

## Stage Flow

Normal level clear flow:

1. Level clears.
2. Any pending reward animations finish or auto-resolve.
3. Level-clear coins are awarded if normal-level coin rewards are enabled.
4. A small non-blocking clear/coin notification appears.
5. The next stage loads.
6. Balls launch automatically.

Boss level clear flow:

1. Boss dies.
2. Any pending reward animations finish or auto-resolve.
3. 1000 boss-clear coins are awarded.
4. Boss element choice screen opens with three valid element choices.
5. Player picks one element.
6. Combo reveal triggers if the new element creates or upgrades the active combo.
7. The next stage loads.
8. Balls launch automatically.

Level 100 exception:
- The campaign cap stays at 100 levels.
- If the level 100 boss is defeated, the run ends in victory.
- The level 100 boss does not need to show an element upgrade choice because there is no next stage.

Reward volume:

- Add one extra brick reward block per level to replace the removed normal stage-clear choice screen.
- These added reward blocks are run-scoped store upgrades.
- Boss clears award 1000 coins for v0.26.
- Normal-level coin rewards can be reviewed later.
- Coins are not selectable normal-level rewards.

Acceptance criteria:

- Normal level clears no longer open `upgradeSelect`.
- Boss clears open an element-only upgrade choice screen.
- Reward choices from normal play happen through blocks, not a post-level menu.
- A clear/coin notification appears without blocking gameplay.
- The next level starts automatically after a short clear beat or boss choice.
- Balls launch automatically after level-to-level transitions.

- Wipe existing saves for v0.26.

- Do not support active runs from the old reward model.

- Bump the save storage key, save version, or config version so old local saves are ignored/reset.
- If an old save is detected, preserve nothing for now.
- Make sure the game boots cleanly into the new default save.
- Keep reset behavior simple because this is only for internal testing.

- The player starts v0.26 with a clean profile.
- Active runs from earlier versions do not continue into the new reward model.
- New rewards follow the catalog split.
